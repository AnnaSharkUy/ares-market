# Заложенные дефекты AresMarket (только для тренера)

Студентам этот файл не показывать.

## Критичные / High

1. **Марсианская локаль → 500**  
   `GET /api/locale/mars` (и mrt, arean, martian) всегда возвращает 500 Internal Server Error.  
   Переключатель в UI вызывает этот эндпоинт.

2. **Остаток на складе не уменьшается** после оформления заказа.  
   Можно заказывать один и тот же товар бесконечно сверх stock.

3. **Корзина: при обновлении quantity = 0** endpoint иногда возвращает тело, несовместимое с response_model (может давать 500 на бэке в некоторых случаях) или странное поведение.

4. **Добавление в корзину сверх stock** после того, как товар уже в корзине — проверка stock только при первом добавлении.

## Medium

5. **Поиск** (`search`) — case-sensitive и только по полю `name`. Описание и бренд не ищутся.

6. **Фильтр max_price** — использует строгое `<` вместо `<=` (граничное значение не попадает).

7. **Несуществующая category** в фильтре — молча возвращает все товары вместо пустого списка / 404.

8. **Итог корзины** (`total_sols`) — не округляется, могут отображаться длинные float (123.456789).

9. **Отзывы** — один пользователь может оставлять несколько отзывов на один товар; рейтинг продукта после отзыва не пересчитывается.

10. **Нет password confirmation** на форме регистрации + слабая проверка сложности пароля.

11. **Сообщение «Not enough stock»** не указывает доступное количество.

## Low / UI

12. **Кнопки фильтров / «В корзину»** — класс `filter-btn-inconsistent` с чуть другим padding.

13. **Длинные названия** товаров — clamp работает не везде идеально на узких экранах.

14. **Top-bar** на очень маленьких экранах может выглядеть перегруженным.

15. **Контраст** вторичного текста (price-credits, muted) — средний, можно отметить как a11y-замечание.

16. **Пагинация** — нет total count / X-Total-Count, сложно понять «есть ли ещё страницы».

17. **При quantity=0 в PATCH корзины** — item удаляется, но клиент может получить неожиданный ответ.

## Как использовать

- Дать задание: найти не менее N дефектов и оформить Bug Reports.
- Отдельно проверить сценарий смены локали на «Марсианский».
- Попросить прогнать API через Swagger/Postman.
- После разбора можно открыть этот файл и сравнить находки студентов с заложенным списком.
